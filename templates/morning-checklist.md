# 早上检查清单（通宵出片之后）

用在环节 8（批量与通宵）。通宵队列跑完或你一早回来时，**按顺序**做；前几步几分钟就能做完。
背景和命令见 `skills/h3-video/references/queue.md`，验片标准见 `skills/drama-scenes/references/qc.md`。**自动检查只用来排出"先看哪几段"，以眼睛和耳朵为准。**

## 早上按顺序做

1. [ ] **队列还活着吗**：`queue.log` 末尾是 `END`、`BEGIN` 还是 `queue stop`；搜 `ERROR`。
   - 末尾：{} 　ERROR 条数：{}
2. [ ] **有没有空转**：`shots.json` 里还有没出的，但 log 一直没有新的 `BEGIN`，多半是依赖的上游没成功（`@` 引用的那条不是 `success`）。
3. [ ] **`results.json` 里有没有非 `success`**，读 `messages`。
   - 失败的 take：{}　原因：{}（常见：二采宽高不是 32 的倍数；锚点没在放大后重加；显存被占）
4. [ ] **核对成片**：用 ffprobe 看宽高（1536×864）、帧率（24）、时长约等于 `frames/24`、有没有音频轨。
5. [ ] **先看联系表**（每段一张 4×2 的八帧图）：扫有没有整段白屏或灰屏、人物变形、场景变样。
6. [ ] **自动检查**：`scripts/review_ep.py` 数每段的硬切数；`scripts/asr.py` 听写台词并对照剧本。
   - 已知误报：起跳、冲击、闪光会被当成切点；同音字、外文名听写会错。
7. [ ] **逐段看原片**：动作有没有演完、结尾姿势和机位、台词是否清楚；不要只看缩略图。
8. [ ] **接缝**：有 `ctx` 的段，用 `scripts/chain_join.py` 生成的 `_接缝.mp4` 看前后是否接得上。
9. [ ] **决定**：留用、换种子重渲，还是改提示词重写（换 take 号），记进 `take-log.md`。

## 回收显卡

- [ ] 队列每段结束都会 `/free`，仍要在换用显卡之前确认：`nvidia-smi` 看已用显存
- [ ] 还高就再发一次 `/free`；仍不降就关掉 ComfyUI 进程（ComfyUI 不会自己释放，加载过的模型会一直占着约 13 GiB）
- [ ] 接着要启动文本模型的话，等显存降下来再启动
