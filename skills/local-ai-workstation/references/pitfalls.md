# 踩坑清单

什么时候读：服务启动失败、出片或文本推理突然变慢、显存不够、结果和预期不符的时候，先在这里按现象找。

已去掉只和作者那台机器有关的条目（某个软件的启动脚本指向、某个端口上残留的具体服务等）。每条都是作者实际踩过的，除非标了"他人报告"。

## 启动失败

| 现象 | 原因 | 处理 |
|---|---|---|
| 引擎一启动就退出，日志为空，退出码 `0xC0000135` | 缺 CUDA 运行库的 DLL（如 `cublas64_13.dll`）。作者的启动器最初依赖了另一个软件沙盒缓存里的 DLL，脱离那个软件就起不来 | 把 CUDA 13 运行库（cudart、cuBLAS、cuBLASLt）放进自己的固定目录，启动前加进 `PATH`。"启动即退出且日志为空"先查这一条 |
| 新版 ComfyUI 报缺依赖 | 新版比旧版多出几个包 | 装进单独的 overlay 目录，只在新版的启动脚本里设 `PYTHONPATH`，见 [comfyui-setup.md](comfyui-setup.md) |
| 模型找不到，但文件"明明在" | 模型是符号链接，源目录被清理或移动了 | 一律放实体文件，不用符号链接 |

## 变慢（没有任何报错）

| 现象 | 原因 | 处理 |
|---|---|---|
| 同一张卡出片慢一倍，日志没警告 | torch 的 CUDA 版本与显卡不匹配（作者实测 `cu128` 下优化算子被静默关闭，`cu130` 正常） | 装与显卡匹配的版本，并用 [comfyui-setup.md](comfyui-setup.md) 里的自检确认优化算子可用。单次实测 |
| 二采突然从 15 分钟变成一小时以上 | 二采分辨率太大，显存超过 16 GB，数据被换到系统内存（共享 GPU 内存）。1.8 倍放大约 47 分钟，1920×1104 约 83 分钟 | 回到 1536×864；`nvidia-smi` 看显存是否顶满。见 h3-video 的 tried-and-dropped.md |
| 稀疏注意力似乎没起作用 | 分辨率或时长变小后 token 数低于 12,288 的门槛；或优化算子没装好 | 看日志里有没有 `sparse producer path` |
| 文本模型生成变慢，引擎日志写 `page-locking refused (out of memory)`、`pinned 0.00 GiB` | Windows 锁页上限约为内存的一半，常驻副本超线 | 3 bit 包加 `resident-budget-gib 45`；NVFP4 在 0.3.3 上无解。见 [llm-basalt.md](llm-basalt.md) |
| 文本模型闲置后第一次测速偏慢一半以上 | 权重要重新读入文件缓存 | 先跑一组丢弃。作者曾把它误记成"原因未明的性能下降" |
| 测速结果忽高忽低、减半 | 测试期间主机上有下载、校验、拷贝或 SSH 读文件 | 测速时不碰主机。作者测到对话速度从 65 掉到 32 tok/s |
| 长时间连续出片后越来越慢 | 他人报告：ComfyUI 内存泄漏，在工作流末尾加清理节点 | 作者的队列每段 `/free`，没有遇到 |

## 显存与切换

| 现象 | 原因 | 处理 |
|---|---|---|
| 出完片后启动文本模型，专家缓存缩小、速度变慢 | ComfyUI 出完片不会自己释放显存，约 13 GiB 一直占着 | 先对 ComfyUI 发 `POST /free`，body `{"unload_models": true, "free_memory": true}`，再启动文本模型 |
| 文本模型和 ComfyUI 同时加载，哪个都跑不动 | 16 GB 不够两边同时放 | 切换前先卸载另一边，见 llm-basalt.md |
| 加载后显存只剩几百 MiB，开浏览器或别的程序就卡 | 这张卡同时驱动显示器 | 不要把显存预留压到极限；跑二采时别开别的吃显存的程序 |

## 工作流与配方

| 现象 | 原因 | 处理 |
|---|---|---|
| 二采报 `shape mismatch` | 首帧、末帧或接续锚点是按一采潜空间尺寸写的，放大后没重加 | 在放大后的潜空间上重加锚点，并单独建一个 guider |
| 二采报 shape 错误（没有锚点） | 二采宽高不是 32 的倍数（1584×912 就会） | 用 1536×864 这类 32 的倍数 |
| 画面正常，成片声音带噪声 | 自己搭两阶段流程时，音频潜变量接错了采样器的输出口。作者有三段成片这样，画面不受影响 | 对照一个已知能出声的工作流接线，出片后听一遍 |
| 首帧类工作流能跑但很慢 | 沿用了参考生视频的 LoRA | FL2V 的 Turbo LoRA 配首尾帧和文生视频，Ref2V 的配参考生视频；换成 FL2V 4 步 LoRA 同样画面只要一半时间（单次实测） |
| 照抄别人的工作流，参数"都对"，结果不对 | 节点上显示的数字可能是摆设，真正的值由变量连线传入 | 沿连线追到参数的真正来源 |

## 评测与比较

| 现象 | 原因 | 处理 |
|---|---|---|
| 看缩略图觉得两版一样，播放原片却差别明显 | 缩小抹掉噪点 | 看原片。见 h3-video 的 quality-eval.md |
| 拿 A 模型作者的配方去比 B 模型 | "同配置"不等于公平，那套配置可能本来就是为 A 写的 | 先去读每个模型作者实际发布的工作流，各按各的最佳用法比 |
| 在 960×544 单次采样上比画质 | 低于 Turbo 类 LoRA 的训练分辨率 | 只把它当两阶段的草稿；比画质用接近成片的分辨率 |
| 把"4 步 LoRA"读成"只采样 4 步" | 它指挂一个 4 步 LoRA，不是采样步数；文件名里的 `8step` 也只是 LoRA 版本 | 去读作者的工作流文件，别凭模型卡一句话 |

## 远程与进程

| 现象 | 原因 | 处理 |
|---|---|---|
| SSH 里启动的服务，断开后就没了 | 会话结束时子进程被杀 | 常驻服务从桌面快捷方式启动；长跑进程用 WMI 创建，见 [remote-access.md](remote-access.md) |
| 中文输出乱码、`&` 和 `%VAR%` 不生效 | 默认 shell 是 PowerShell 5 | 用 `;` 和 `$env:VAR`，输出前设 UTF-8 |
| 换队列脚本后同一段被渲了两遍 | 杀进程后 ComfyUI 里的任务还在跑，重启又提交一次 | 用 STOP 文件停队列，见 h3-video 的 queue.md |
| 机器上有旧服务占着另一个端口，配置和现用的不同 | 早期试验留下的进程 | 先列出监听的端口和进程，确认每个端口属于谁，别混用 |
| 下载走了代理，流量被耗尽 | TUN 模式的代理软件在系统层接管流量，下载器的"不走代理"参数不起作用 | 见 [china-network.md](china-network.md)：1 字节请求加代理日志确认直连 |
