# 国内网络下直连下载模型

什么时候读：要在国内网络下载大模型（几 GB 到上百 GB），尤其是主机上开着代理软件的时候。

核心规则：**下载前先报体积；确认走的是直连，不是代理；下载后校验 SHA-256。** 为什么：作者的代理流量被一次大下载耗尽过两次，一次是某个 agent 走官方源下了 131 GB，一次是 14.7 GB 被代理软件的 TUN 模式悄悄分到了代理节点。

## 首选魔搭 ModelScope

- 在国内，魔搭的域名通常命中代理规则里的"国内直连"。作者的规则下，`www.modelscope.cn` 和 `cdn-lfs-cn-1.modelscope.cn` 都走直连。**以你自己的规则和日志为准，下面的检查必须做。**
- 文件清单接口会给出每个文件的大小和 SHA-256，下载前先看：
  `https://www.modelscope.cn/api/v1/models/<所有者>/<仓库>/repo/files?Recursive=true`
- 下载地址：
  `https://www.modelscope.cn/models/<所有者>/<仓库>/resolve/master/<文件路径>`
- 视频相关的模型，作者多数是从魔搭取的（官方底模、潜空间放大模型、超分模型等）。有些创作者把整合包只放在网盘（如夸克）里，通常要在网盘客户端里登录后下载，网盘是国内服务，不经过代理；下载前同样先报体积。

## 开着 TUN 模式的代理软件：下载器的"不走代理"参数不起作用

TUN 模式在系统层接管所有流量。`curl --noproxy`、`aria2c --no-proxy`、清空 `HTTP_PROXY` 环境变量，**统统管不住它**。走不走代理只由代理软件的规则决定。

所以不能靠参数，要**用请求实测、再查代理日志**。

### 开始任何大下载前

1. 对目标地址发一个 1 字节的请求，看实际连到了哪个 IP：

```powershell
curl.exe -sL -r 0-0 -o NUL -w "%{remote_ip}  %{http_code}  %{url_effective}\n" "<下载地址>"
```

2. 在代理软件的连接日志里搜目标域名，看这一行结尾是不是直连（Clash 系列的日志目录里会写 `using ...[DIRECT]` 或 `[节点名]`）。结尾是直连才继续；是节点名就停下，换源。
3. **下载中途再查一次。** 重定向到的 CDN 域名可能命中另一条规则：第一跳直连，第二跳被分到了代理。

### 判断是不是直连

- 看 `remote_ip`：如果它落在代理软件的虚拟地址段，说明流量被代理软件接管了，要看日志里它转给了谁。Clash 的默认虚拟段是 `198.18.x.x`、`2001:2::`、`fdfe:`（别的软件不同）。
- 反过来，`remote_ip` 是真实地址、代理日志里又查不到该域名，就是没经过代理。清华 PyPI 镜像和魔搭有时会解析到真实地址（校园网原生 IPv6 或阿里云 IP），此时日志里没有记录，这是正常的直连。

## 有些镜像站会被分到代理

`hf-mirror.com`、`hf-mirror.net` 用的是 Cloudflare 的 IP，会命中代理规则里针对 Cloudflare 的那一条，被分到代理节点。**它们"能直接返回数据"不等于没走代理。** 用上面的方法验证过再用。

镜像不支持续传，或要跳转到官方源时，**就停下来，不要回退官方源**：回退意味着绕过你刚确认过的直连。

## pip 包

用国内镜像，例如清华：`pip install --index-url https://pypi.tuna.tsinghua.edu.cn/simple <包>`。同样可能不经过代理软件，同样用日志验证。

## 下载后校验 SHA-256

大文件下完不校验，坏文件会在出片时表现成莫名其妙的报错。拿魔搭清单里的 SHA-256 对：

```powershell
Get-FileHash <文件> -Algorithm SHA256          # PowerShell
certutil -hashfile <文件> SHA256                # cmd
shasum -a 256 <文件>                            # macOS、Linux
```

不一致就重下，不要"先用着"。从别的地方复制或移动大文件到模型库之后也校验一次（作者把编码器复制成实体文件后就逐个校验了）。

## 每次大下载的流程（给 agent 的清单）

1. 报告：要下载什么、多大、从哪个域名、存到哪。等用户同意。
2. 1 字节请求加代理日志，确认直连。
3. 开始下载，中途再查一次日志。
4. 下完校验 SHA-256，核对大小。
5. 删除任何文件之前逐项向用户确认（磁盘紧张时尤其如此）。
