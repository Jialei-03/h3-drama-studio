# 拼接与音轨重建

> 什么时候读：要把留用片段按顺序拼成整片时；拼好的片音画不同步、最后一个字被截时；武戏接续段要剪掉上下文帧并做颜色匹配时。

可信度：下面的做法在《Gemini的复仇！》24 段拼接里全程使用，除特别标注外为**已验证**。

## 1. 流程总览

```
清单 clips.yaml（顺序 + 每段用哪个文件 + 可选的裁剪帧）
  → splice.py：逐段规范化（分辨率、帧率、采样率、音画等长）→ concat 拼接（画面直接复制）
  → fix_audio.py：重建一条连续音轨
  → 检查（帧数、音画长度、接缝）
```

对应脚本：`scripts/splice.py`（按清单拼接）、`scripts/chain_join.py`（接续段处理）、`scripts/fix_audio.py`（重建音轨）。分辨率和帧率读 config.yaml 的 `project.width / height / fps`（示例 1536×864、24 fps），也可以写在清单里或用命令行覆盖。

```
python3 scripts/splice.py clips.yaml -o build/full.mp4              # 拼接；终端会提示下一步必做重建音轨
python3 scripts/fix_audio.py build/_splice_work/full.list.txt build/full.mp4 build/full_fixed.mp4
# 或者一步做完（等价）：
python3 scripts/splice.py clips.yaml -o build/full.mp4 --fix-audio
```

## 2. 清单驱动

拼接清单是一份 yaml（示例：`examples/gemini-revenge/data/clips.example.yaml`）：每条一个片段，按播放顺序。

| 字段 | 含义 |
|---|---|
| `file` | 片段文件；也可以写成候选列表，第一个存在的赢 |
| `start_frame` / `end_frame` | 可选：只用 `[start_frame, end_frame)` 这几帧（含头不含尾，帧序号从 0 起，按这个文件自己的帧数）。这是"剪帧"改稿的写法，改数字即可，不用另存文件 |
| `group` | 可选：`--group fight` 只拼这一组（例：同一份清单既出全片，又出"只有打戏"的版本） |
| `chain: true` | 接续段：必须找到 `_接` / `_接剪` 版本，找不到就报错，不允许退回原片（原片头部还带着上下文帧） |
| `exact: true` | 这条就用写的这个文件，不自动找后缀 |
| `label` | 可选：终端输出里显示的名字 |

清单顶层还有 `output`、`width` / `height` / `fps`、`prefer_suffixes`（见下）。清单里的相对路径相对于清单文件所在目录。

同一段有多个版本时，规则固定为"最精的那个优先"（`prefer_suffixes`，默认 `["_接剪", "_接"]`）：

| 文件 | 含义 |
|---|---|
| `段名_take.mp4` | 生成出来的原片 |
| `段名_take_接.mp4` | 接续段：已剪掉头部 22 帧并做了颜色匹配（`chain_join.py` 的输出） |
| `段名_take_接剪.mp4` | 在 `_接` 基础上又手工剪过内部（改稿清单里的"剪帧"；现在更推荐用 `start_frame` / `end_frame`） |

清单里写 `段名_take.mp4`，脚本依次找 `_接剪`、`_接`，取存在的第一个，都没有才用原片；用了哪个文件，终端会逐条列出来。为什么用清单而不是文件夹排序：改稿时只改清单里的一行，不会误拼进旧 take；清单本身也是"这版成片由什么组成"的记录。

`splice.py --dry-run` 只列出每段实际用哪个文件、多少帧，不编码；改完清单先跑一遍。

## 3. 片段规范化

每一段先单独转成**完全一致**的格式再拼：

| 项 | 做法 |
|---|---|
| 画面 | 缩放到 `width×height`、`setsar=1`、`fps=24`；重编码 H.264、crf 16、preset slow、yuv420p |
| 声音 | 重采样 48 kHz、双声道；先补静音再截到**和画面一样长**；AAC 192k |
| 帧数 | 用 `ffprobe -count_frames` 数**实际帧数** n，输出 `-frames:v n`；不要信容器里的时长 |
| 裁剪 | 清单里写了 `start_frame` / `end_frame` 的，画面按帧、声音按同样的时刻一起剪 |
| 没有音轨的段 | 补静音（`anullsrc`），不会因为缺音轨而中断 |

规范化结果按（源文件、裁剪、规格）缓存在工作目录（默认 `输出目录/_splice_work`，`--work-dir` 可改），清单里只改一行时其余段不重新编码。

为什么：concat 直接复制要求所有片段的流参数完全一致；而某一段声音比画面短或长几十毫秒，拼出来就整体错位，越往后越明显。逐段强制音画等长，是为了让误差不跨段累计。

## 4. 为什么必须重建音轨

concat 复制各段 AAC 时，接缝处的时间戳会重叠，解码出来的音频**比画面长**。《Gemini的复仇！》v16 的 24 段拼完，音频比画面多出 0.75 s（约每个接缝 30 ms，按 0.75 s ÷ 24 段推算），越往后字幕越晚，最后一个字被截断。2026-11-24 用本仓库的脚本复测：12 段拼完，解码实测音频比画面长 0.387 s（约每段 32 ms），重建后差 +0.003 s [已验证]。

**注意：不能用 `ffprobe` 的容器时长来查这个问题。** 同一个文件，容器里的音轨时长只比画面长 0.021 s，而真正解码出来长了 0.387 s。要看**解码实测**：`splice.py` 和 `fix_audio.py` 结束时打印的就是这个数；手工查：`ffmpeg -v error -i 成片.mp4 -map 0:a:0 -ac 1 -ar 48000 -f f32le - | wc -c`，字节数 ÷ 4 ÷ 48000 就是秒数，和画面时长比（不要看 `-f null` 打印的 `time=`，它按时间戳算，同样看不出多出来的采样）。

解决：用 `scripts/fix_audio.py` 重建。它做三件事：
1. 逐段解码已规范化片段的音频，按**该段自己的帧数**精确截成 `n / fps × 48000` 个采样（不够补零；非整数帧率时按累计取整，不累积漂移）；
2. 把所有段连成一条连续的 PCM，**只编码一次**（AAC 256k）；
3. 和拼好的画面（直接复制）合成。

用法：`python3 scripts/fix_audio.py LIST.txt VIDEO_IN.mp4 OUT.mp4 [--fps 24] [--sr 48000] [--bitrate 256k]`。`LIST.txt` 是 concat 清单（`file '路径'` 的格式，`splice.py` 写在工作目录里，文件名是 `输出名.list.txt`），`VIDEO_IN.mp4` 是用这份清单拼好的视频；脚本会核对各段帧数之和等于 `VIDEO_IN` 的帧数，对不上就停下。`splice.py --fix-audio` 把两步合成一步。

**重建音轨是拼接后的第一件事，之后才做冲击帧、字幕、配乐。** 为什么：字幕、配乐、歌词的时间都是在这条音轨上测的；音轨后来变了，所有时间都要重做。

拼完必查：
- 画面时长和音轨**解码实测**时长相差不超过 1 帧（脚本会打印，超了报错；见上一段的注意）；
- 最后一句台词的最后一个字完整；
- 总帧数 = 各段（裁剪后）帧数之和，`splice.py` 会打印。

## 5. 接续段：剪掉上下文帧，做颜色匹配

武戏逐段生成时，每个新段把上一段**末尾 22 帧（约 0.92 s，24 fps）连同声音**锚在第 0 帧上生成，让动作、机位自然接上（接续方案来自创作者惊尘；生成端怎么做见 [drama-scenes 的 continuation.md](../../drama-scenes/references/continuation.md)）。这 22 帧只是上下文，不属于新段的内容，拼接时必须剪掉。

`scripts/chain_join.py PREV.mp4 NEW.mp4 [--n 22] [--strength 0.75] [--secs 3] [--out-dir DIR]` 做的事：

1. 剪掉 NEW 的前 n 帧，声音同步剪掉同样长度，并补静音/截到和画面一样长（输出音画等长）。`--n` 必须和生成时用的帧数一致。
2. **颜色匹配**：取"剪掉之后的第一帧"和 PREV 的最后一帧，缩小到 384×216，逐通道（R/G/B）把均值和标准差对齐，强度 0.75（0 = 不改，1 = 完全对齐），同一套增益和偏移施加到整段。0.75 是经验值，没有和别的强度对比过 [未验证最优]。`--no-color` 只剪帧不调色。
3. **大修正不做**：任一通道增益偏离 1 超过 `--max-gain`（默认 0.12），或偏移超过 `--max-offset`（默认 15，0–255 刻度），说明两帧本来就是不同的东西（硬切或白光），不是色彩漂移，此时跳过匹配，只打印提示。例：f2→f3 两边都是满屏白光，不做颜色匹配。
4. 输出两个文件（默认和 NEW 同目录，`--out-dir` 改到别处）：`_接.mp4`（进拼接清单）和 `_接缝.mp4`（PREV 最后 `--secs` 秒 + 新段，专门用来看接缝；`--no-seam` 不出）。终端最后一行是 JSON 汇总（输出路径、帧数、增益、偏移、是否跳过调色）。

2026-11-24 复测：用一对真实的接续片段（260 帧，开头 22 帧是上下文），输出 238 帧，第 0 帧和原片第 22 帧一致（PSNR 44 dB，不调色时）[已验证]。

接缝必看项（看 `_接缝.mp4`，不要只看拼好的全片）：
- 人物站位、朝向、持械手、伤痕是否延续；
- 机位有没有突然跳变（大的、不合理的跳变要重出，小误差可以靠硬切掩过去）；
- 颜色有没有一跳（匹配后仍然明显，就换种子或改用硬切）；
- 声音有没有断、重叠。

不接续的文戏段：站位对上、停在完整节点就可以硬切，不需要剪上下文，也不需要颜色匹配。

## 6. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 越往后字幕越晚 / 最后一个字被截 | concat 复制 AAC 造成音轨偏长（容器时长看不出来，要看解码实测） | 重建音轨（第 4 节） |
| 接缝处闪一下颜色 | 接续段没做颜色匹配，或两帧本来就是硬切 | 查 `_接缝.mp4`；白光接缝不匹配是正常的 |
| 接缝处动作重复一小段 | 上下文帧没剪干净（`--n` 和生成时不一致） | 核对生成时的帧数 |
| 个别段声音比画面短 | 规范化时没补静音 | `splice.py` 已对每段补静音再截齐；自己手工规范化时检查 `apad` 和 `atrim` |
| 拼出来的片比各段加起来长 | 用了容器时长而不是实际帧数 | 一律用 `-count_frames` |

## 7. 画质提示

规范化、冲击帧、字幕、歌词各会重编码一次画面（都用 crf 16、preset slow）；配乐一步画面直接复制。固定的步骤顺序（见 SKILL.md）把重编码次数压到了最少。是否有可见劣化，以你看原片为准，不要只看缩略图。不要把一采预览（低分辨率）的片段拼进成片。
