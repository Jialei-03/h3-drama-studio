# 歌词字幕

> 什么时候读：用户**提供了有授权的歌词文件**，想在成片的配乐段显示中英对照歌词时。用户没有歌词文件，就不要做歌词字幕。

可信度：样式和时间公式是《Gemini的复仇！》最终成片用的（**已验证**：56 对歌词里，配乐段内有时间的 28 对全部显示）；时间表的打点方式是**单次实测**。

## 1. 红线（先读这一节）

| 规则 | 为什么 |
|---|---|
| 只读取**用户提供的、有授权的歌词文件** | 歌词受版权保护，来源和授权由用户负责 |
| **不由 AI 听写歌词，也不由 AI 翻译歌词**；中文行也来自用户的文件 | AI 听写会听错，翻译也可能侵权；用户只给了英文，就只显示英文，让用户自己提供译文 |
| **脚本不打印歌词**：终端输出、日志、聊天回复、提交记录里都不出现歌词文字 | 日志和聊天容易被转发、被收录 |
| 歌词文件、带歌词文字的时间表、含歌词的成片，都放在仓库之外或 `.gitignore` 里 | 本仓库不含任何歌词、歌曲 |
| 时间表里**只存对号和秒数，不存歌词文字** | 带文字的时间表本身就是一份歌词副本（作者早期的表带了文字，所以开源版改成只用对号） |

## 2. 输入

- **歌词文件**：UTF-8 文本，非空行，**英文一行、中文一行交替**（例：第 1 行英文、第 2 行中文、第 3 行英文……）。脚本会检查行数成对，不成对就报错停止。
- **时间表**：每一对歌词（用**对号**表示：去掉空行后，英文一行 + 中文一行算一对，从 1 起数）对应原曲里的起止秒，秒数写 `90.5` 或 `1:30.5` 都行。没有歌声的间奏不填，那几对会被跳过。`.tsv` 每行 `对号<TAB>起<TAB>终`（`#` 开头是注释），`.yaml` 写成 `pairs: {1: [起, 终], ...}`；示例 `examples/gemini-revenge/data/lyrics_times.example.tsv`（占位数字）。
- **原曲音频**：只在打点（第 3 节）时用；`render_lyrics.py` 本身不读歌曲，也不做识别。
- **偏移 `OFF` 和音乐范围**：和 [bgm.md](bgm.md) 里的同一个常数，**片中时间 = 原曲时间 + OFF**。`--offset OFF --range 起,止` 直接给；更推荐 `--bgm-plan 配乐.yaml`，脚本从 mix_bgm 用的同一份 yaml 里算 OFF（含 `shifts` 平移）和音乐范围，剪过片只改配乐 yaml 一处。

## 3. 时间表怎么打点

1. 用逐词识别、节拍和能量分析**定位**"原曲的哪一段时间在唱第几对歌词"。识别出来的文字只用来找时间，**不当歌词使用，不输出**；识别效果差（歌声被伴奏盖住）时，让用户自己给出每对歌词的开始时间。
2. 按歌曲结构（主歌、副歌、间奏、过渡）核对：同一行内容在副歌里重复出现，要分别打点；相邻两对的时间段不重叠。
3. 做成 `对号 → (起, 止)` 的表。作者这首歌共 56 对歌词，其中 28 对在配乐范围内、打了点。
4. 用成片抽查：开头、中间、结尾各听一对，看歌词是否对着歌声。

## 4. 每张卡的时间（公式）

设一对歌词在原曲里的起止是 `a`、`b`，下一对的起点是 `a_next`：

| 量 | 公式 |
|---|---|
| 片中起点 `s` | `a + OFF − 0.1`（比歌声略早 0.1 s 出现） |
| 片中终点 `e` | `min( max(b + OFF + 0.3, s + 1.0), a_next + OFF − 0.12, s + 7.5 )` |
| 范围 | 只保留落在配乐范围内的句子；第一句不早于配乐开始后 0.3 s |
| 淡入淡出 | 各 0.25 s（卡片很短时取时长的 1/4） |

为什么 `s` 略早：让观众先看到字再听到歌，读得跟得上（推断，未单独对比过）。

## 5. 样式与位置

按 1536×864 写，其他分辨率等比缩放。

| 项 | 值 |
|---|---|
| 结构 | 双语两行：英文在上，中文在下，整块居中 |
| 英文 | 斜体衬线字体，30 px（作者用 Baskerville SemiBold Italic）；字体文件路径写在 config.yaml 的 `fonts.en_italic`（`.ttc` 再配 `fonts.en_italic_index`），没配会报错 |
| 中文 | 和对白字幕同款：苹方 SC Regular 34 px，汉字之间加 3 px 字间距（`fonts.zh`、`fonts.zh_index`） |
| 行首符号 | 每行前加 `♪`，单独用带符号字形的字体画（作者用 Arial Unicode，26/29 px；`fonts.symbol`，没配就用 `fonts.zh` 画，显示成方框就配它；`--no-note` 可不画），与文字间隔 9 px |
| 颜色 | 暖白 RGB(242, 240, 235) |
| 阴影与暗边 | 阴影：高斯模糊 6 px、90% 黑；细暗边：膨胀 1 px、RGB(10, 10, 10)、70% 不透明 |
| 位置 | 底部居中；歌词块底边离画面底边 128 px，也就是在对白字幕（64 px）的**正上方** |

为什么放在对白字幕上方：对白是主，歌词是背景的背景；两者同时出现也不重叠、不互相遮挡。放在画面上方会和角色头顶、特效抢位置。

## 6. 渲染

```
python3 scripts/render_lyrics.py 歌词.txt 时间表.tsv IN.mp4 OUT.mp4 --bgm-plan 配乐.yaml
python3 scripts/render_lyrics.py 歌词.txt 时间表.tsv IN.mp4 --offset -27.4 --range 80.7,161.6 --preview   # 先看样式
```

1. 读歌词文件、检查成对、套用时间表和第 4 节的公式（`--lead 0.1 --tail 0.3 --min-dur 1.0 --max-dur 7.5 --gap 0.12 --edge 0.3 --fade 0.25` 可调）；
2. 每对歌词画成一张透明 PNG，用 ffmpeg `overlay` 链叠到成片上；
3. 画面 libx264 crf 16 重编码；**音轨和封面流直接复制**（成片带封面流时才映射 `0:v:1`，并 `-disposition:v:1 attached_pic`）。

`--preview` 只合成前三句、存成图片（`--preview-dir`，默认 `./lyrics_preview`），先看样式再整片渲染。`--zh-first` 用于歌词文件里中文在前的情况；`--bottom` 调整歌词块位置（默认 128 px）。

脚本的输出只有一行汇总（例：`歌词 56 对，时间表给了 28 对，落在片中音乐范围（80.7–161.6 s）内 N 句；OFF=-27.553`）和每句的片中起止时间，**没有歌词文字**；失败时也不回显 ffmpeg 的报错（`--verbose` 才显示，滤镜图里只有位置和图片名）。改脚本时保持这一点。

2026-11-24 用我们自己编的两三对无意义占位文本（不是任何真实歌词）复测 [已验证流程]：时间公式与第 4 节一致（例：原曲 10.0–13.0 s、OFF=+5 → 片中 14.9–18.3 s）；`--bgm-plan` 算出的 OFF 和范围与配乐 yaml 一致；带封面流的成片渲染后封面流仍在、音轨 md5 与输入一致；终端输出里没有任何歌词文字。

歌词是**最后一步**：它依赖最终的时间线（配乐偏移已经定了）。之后任何时间变动，只需要在带配乐的成片上重跑这一步。

## 7. 验收

- 开头、中间、结尾各抽一对，歌词比歌声略早出现、不晚；
- 和对白字幕同时出现时不重叠；
- 歌词只出现在配乐范围内；
- 日志、聊天、仓库里搜一遍，确认没有歌词文字；
- 样式预览通过后再整片渲染（整片要重编码，比较慢）。

## 8. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 歌词整体偏早或偏晚 | `OFF` 没有跟着剪点更新 | 重新算 `OFF`（[rough-cut.md](rough-cut.md) 第 6 节） |
| 副歌第二遍的歌词没出现或错位 | 时间表里只给了第一遍 | 每遍分别打点 |
| `♪` 显示成方框 | 文字字体没有这个字形 | 用带符号字形的字体单独画 |
| 歌词盖住了对白字幕 | 歌词块底边设得太低 | 底边 128 px，对白 64 px |
| 用户只给了英文歌词 | 没有授权的中文译文 | 只显示英文，不替用户翻译 |
