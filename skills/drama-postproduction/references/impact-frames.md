# 冲击帧

> 什么时候读：想给打戏里真正的大招加"一闪而过的 2D 冲击画面"时；冲击帧看起来卡、乱、和画面对不上时；剪过片后要挪冲击帧位置时。

做法来自创作者**不会玩ai的凌大壮**的冲击帧教程（B 站），这里只写我们学到的方法和最后定下的参数，不复制他的提示词。冲击帧是**后期插进去的**，不是视频生成时画出来的。

可信度：下面的排法在《Gemini的复仇！》全片 5 处冲击里用过，用户逐版看片后定稿，为**已验证**；九宫格的出图耗时等为**单次实测**。

## 1. 原理：一处冲击 = 一张九宫格 + 一张时间表

1. 挑一个真正的大招：找到**爆发的那一帧**（声音最响、画面最亮的瞬间），把这一帧截成图。
2. 让图像模型以这张截图为参考，出一张 3×3 九宫格（九格同样大，每格 16:9，细黑线分隔，无文字无编号）：
   - 前三格：带人物和场景的 2D 冲击画面（和截图是同一个瞬间）；
   - 第 4 格：纯特效、黑底，**最亮、最有冲击力**；
   - 第 5–8 格：黑底特效，从无到有地长出来；
   - 第 9 格：特效熄灭的瞬间。
3. 按下面的时间表，把其中 3–4 格作为全画幅图片叠到那几帧上。

提示词的结构（自己写，不要照搬）：身份与任务一句话 → 参考图里发生了什么、要表现的特效是什么 → 九格各画什么 → 配色 → 限制 → 版式。关键点：
- **配色跟着原片的色调走**：主色取自截图里那个招式的颜色，辅色一两个。作者的片是紫、银白、黑；教程原版是红黑白。
- **限制里必须写"画面简约、干净，不要碎小纹理和颗粒"**：不写，一闪而过会显得脏、乱。
- 风格限定为 2D、硬边色块、放射速度线，明确排除写实和 3D。
- 图像模型用 config.yaml 的 `image_api`（兼容 OpenAI 图像接口的服务，要支持传参考图）。整张九宫格出 1536×864，每格约 512×288，放大到全画幅只闪 2 帧，够用；一张约 45 秒 [单次实测，视服务而定]。

## 2. 时间表（定稿参数）

24 fps 下，每处这样排：

```
[格A 第1帧 108%放大][格A 第2帧 100%] [原画面1帧]
[格B 第1帧 108%][格B 第2帧 100%]     [原画面1帧]
[最亮格 ……]                           [原画面1帧]
[后一格 ……]                           [原画面1帧]
（需要时）[负片×3][原画面×2][负片×3]
```

| 参数 | 值 | 为什么 |
|---|---|---|
| 每格停留 | **2 帧**，第 1 帧放大到 108%，第 2 帧回到 100%（放大回弹） | 1 帧一闪太乱，看不清 |
| 格与格之间 | **隔 1 帧原画面** | 画面一直在动，不会像停住 |
| 每处几格 | 3–4 格：最亮格之前 2 格，最亮格，之后 0–1 格 | 从弱到强，在声响那一刻到顶 |
| 最亮格的位置 | **起始帧 = 声响峰值那一帧**；其余格向前排 | 让最亮的一闪和声音撞在一起 |
| 负片 | 只用在"结果瞬间"（爆炸、白光吞没）：峰值后接 3 帧负片、2 帧原画面、3 帧负片 | 两下反色闪，像余波 |
| 声音 | **不动** | 只换画面，片长不变，音轨原样复制 |

为什么不让每张静止停 6 帧：画面停住而声音继续，观众会觉得"卡了"，节奏全乱。（用户看片反馈）

一处的总长约 0.4–0.9 秒（9–21 帧）。

## 3. 放在哪

- **只放在真正的大招和撞击上**：作者全片 3 分 44 秒只有 5 处。例：龙口扑向镜头、两个召唤物炸开、光刃砍中擂台的白光、能量球爆开、龙环光束命中。用户看片时删掉了"剑掌对砍"那一处，因为它不是大招。
- **不要盖住用户想看的过程**：能量球一点点变大、角色走位这些，冲击帧要放在结果上，不放在过程里。
- **每处的九宫格必须从"插入位置那一帧"生成**：用别处的截图生成，出来的画面和前后对不上（"和画面不符"），要重出。作者有两处重出过。
- **峰值帧要实测**：用声音峰值或逐帧亮度找，再肉眼确认，不要靠估。冲击帧位置写的是**帧号**，不是秒。

## 4. 实现

`scripts/impact_frames.py 冲击表.yaml IN.mp4 OUT.mp4`：输入成片和一份冲击表（示例：`examples/gemini-revenge/data/impacts.example.yaml`），输出**同帧数**的新片。表里的帧号对应**当前这版成片**的时间线。

冲击表的字段：

| 字段 | 含义 |
|---|---|
| 顶层 `fps` / `zoom` / `panel_frames` / `gap_frames` / `margin` | 默认 24 / 1.08 / 2 / 1 / 5（第 2 节的定稿参数）；单处冲击里写同名字段可以覆盖 |
| 顶层 `negative_pattern` / `negative_delay` | 负片的排法：`#` = 负片帧，`.` = 原画面，默认 `"###..###"`；紧接最后一格之后，再空 `negative_delay`（默认 1）帧 |
| 顶层 `shifts` | 可选：`[{at_frame: 帧号, delta_frames: 增量}]`。剪过片，只加一行，下面所有帧号不用逐个改 |
| `impacts[].grid` | 九宫格图（相对路径相对于冲击表）；`layout` 可改成别的行列数（默认 `3x3`） |
| `impacts[].peak_frame` | 声响峰值那一帧 = 最亮格的第 1 帧 |
| `impacts[].peak_panel` / `before` / `after` | 最亮格的格号（默认 4）、之前用哪几格、之后用哪几格。**格号从 1 起**，按九宫格从左到右、从上到下数 |
| `impacts[].negative` | 要不要接负片 |

辅助：
- `--dry-run`：只打印每一帧换成什么（例：`2239:格4↑` 表示第 2239 帧放第 4 格的放大版），并检查帧号越界、两处冲击撞帧。渲染前先看一遍。
- `--find-peak 起,止 IN.mp4`：不渲染，在这段秒数里列出"声音最响""最亮""亮度突增最大"的几帧，帮你定位峰值帧；只是提示，**必须再截图肉眼确认**。

脚本做的事：
- 每一格从九宫格里裁出来（四周各让 `margin` 像素，去掉分隔线），缩放到成片的全画幅；放大版从中心裁 1/1.08 再放大；
- 用 ffmpeg `overlay` 的 `enable='eq(n,帧号)+…'` 只在指定帧上叠图；负片用 `negate` 后同样按帧号叠；
- `-c:a copy` 复制音轨；画面 crf 16 重编码。

2026-11-24 用纯色九宫格在一段真实成片截取（192 帧）上复测：被改的帧正好是表里列的 18 帧，格与格之间的间隔帧、负片中间的 2 帧原画面都保持原样，负片帧等于原帧反色，输出帧数不变，音轨 md5 与输入一致 [已验证]。

## 5. 顺序与连锁

- **冲击帧在字幕之前做**：冲击图是全画幅覆盖，后做会盖住已经叠好的字幕。
- 它会丢掉封面流，所以封面在它之后嵌入（见 SKILL.md 的顺序）。
- 剪过片之后帧号全部要改：剪掉 N 帧，其后每处帧号 −N（作者剪 20 帧，五处帧号都减了 20）。规则见 [rough-cut.md](rough-cut.md) 第 6 节。
- 做完核对：总帧数和上一版相同；音轨未变；每一处逐帧看一遍（峰值格是否落在声响上，有没有盖住字幕）。

## 6. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 一闪太乱、看不清 | 每格只有 1 帧 | 每格 2 帧 + 隔 1 帧原画面 |
| 画面"卡住"一下 | 每格停留过久（作者试过 6 帧） | 回到 2 帧 |
| 冲击画面和前后内容对不上 | 九宫格不是从该帧生成的 | 用该帧重新出图 |
| 画面脏、碎纹理多 | 提示词没限制细节 | 加"简约、干净"的限制 |
| 冲击帧没落在声响上 | 用估计的帧号 | 实测峰值帧 |
| 剪片后冲击帧错位 | 帧号没跟着剪点平移 | 帧号 −N |
