# 短剧后期：粗剪、拼接、冲击帧、字幕、配乐

从"所有留用片段出齐"到"可以交付的成片"。本 skill 的核心是两件事：**步骤顺序不能换**，和**任何一处改动都会让它后面的时间全部平移**。

成片规格示例（《Gemini的复仇！》）：1536×864、24 fps、H.264 + AAC 256k、224 秒、整合响度约 −14.9 LUFS、真峰值 −1.6 dBTP。分辨率和帧率读 config.yaml 的 `project.width / height / fps`，字体读 `fonts.zh / en_italic`。

## 固定顺序

| 步 | 做什么 | 脚本 | 细节 | 为什么在这一位 |
|---|---|---|---|---|
| 0 | 编号全片给人审、改稿、剪辑方案 | — | [rough-cut](references/rough-cut.md) | 在动任何一帧之前，先让用户批准要剪什么 |
| 1 | 按清单拼接；武戏接续段剪掉上下文帧、做颜色匹配 | `splice.py`、`chain_join.py` | [splice](references/splice.md) | 后面所有步骤都建立在这条时间线上 |
| 2 | **重建音轨** | `fix_audio.py`（或 `splice.py --fix-audio`） | [splice](references/splice.md) | concat 复制 AAC 会让音轨比画面长（要看解码实测，容器时长看不出来）；后面所有时间都在这条音轨上测 |
| 3 | 冲击帧 | `impact_frames.py` | [impact-frames](references/impact-frames.md) | 它是全画幅覆盖，后做会盖住字幕；只换画面，不动声音；这一步也会丢掉封面流 |
| 4 | 字幕 | `retime_subs.py`、`render_subs.py` | [subtitles](references/subtitles.md) | 在修好的音轨上对时；这一步会丢掉封面流 |
| 5 | 嵌入封面 | `embed_cover.sh` | `drama-publish` 的 covers.md | 配乐和歌词两步会把封面流带过去，封面做好后一次嵌入即可 |
| 6 | 配乐 | `mix_bgm.py` | [bgm](references/bgm.md)、[loudness](references/loudness.md) | 画面直接复制，字幕已在里面；对齐用冲击帧的位置 |
| 7 | 歌词 | `render_lyrics.py` | [lyrics](references/lyrics.md) | 依赖最终时间线；任何变动只重跑这一步 |

封面还没做好时，可以先跳过第 5 步，最后用 `embed_cover.sh` 补嵌（不重编码，几秒；2026-11-24 复测码流 md5 与输入一致）。

## 决策表

| 用户说 / 现象 | 做什么 | 读 |
|---|---|---|
| "先看看整片" "哪里要改" | 出编号全片，不剪、不加字幕、不加配乐 | rough-cut §2 |
| 用户给了零散意见 | 整理成改稿清单，再写剪辑方案，等批准 | rough-cut §3–4 |
| 一处不行：剪帧、补镜、还是换段 | 用最便宜且能解决的 | rough-cut §5 |
| 定稿后再改一段 | 从最早受影响的阶段重跑，平移所有时间 | rough-cut §6 |
| 越往后字幕越晚 / 最后一个字被截 | 重建音轨，再重测字幕 | splice §4 |
| 接缝处闪色、动作重复 | 看 `_接缝.mp4`，核对 `--n` 和颜色匹配 | splice §5 |
| 大招不够炸 | 在真正的大招上加冲击帧 | impact-frames |
| 加字幕 / 字幕对不上 | 文字以剧本为准，音轨上逐词对时 | subtitles |
| 加背景音乐 | 反推对齐、校平、混音 | bgm |
| 音乐"忽大忽小""像被剪过""对不上拍" | 校平；实测鼓点重新对齐 | bgm §3–4 |
| 加歌词 | 只读用户提供的有授权歌词文件 | lyrics |
| "太响""太轻""爆音" | 量响度和真峰值；加原声增益、调限幅 | loudness |

## 必须遵守的规则

1. **先给方案，批准后再动手。** 任何要剪掉、替换的内容，列出位置、动作、理由、对后面的影响，用户批准后才做。为什么：做进带字幕和配乐的成片后，撤销要重做后面所有步骤；2026-11-21 用户明确要求。
2. **拼接后第一件事是重建音轨。** 为什么：concat 复制 AAC，24 段拼完音频多出 0.75 s，字幕越往后越晚、最后一个字被截。
3. **字幕文字以剧本为准，时间在修好的音轨上用逐词转写测。** 为什么：识别会听错人名；在没修的音轨上测，之后全部作废。
4. **冲击帧每张只闪 2 帧、中间隔 1 帧原画面，只放在真正的大招上，只换画面不动声音。** 为什么：1 帧一闪太乱；停 6 帧会让画面停住而声音继续，像卡了。
5. **配乐只当背景，音乐不剪，电平全程一致，不压低原片声音。** 为什么：用户一听就说"好像剪辑了"；早期"压低原声给歌词让路"的做法已被否决。
6. **配乐从结尾反推对齐，按实测鼓点起音。** 让高潮收尾那句的重拍落在最后一个大招的冲击帧上。为什么：按逐词识别时间对，曾差一拍（约 0.6 s）。
7. **混音后限幅，真峰值 −1.5 dBTP 以下；量编码后的成片。** 为什么：提完原声增益，爆炸瞬间的峰值会超过 0 dBFS。
8. **歌词只读取用户提供的、有授权的歌词文件；脚本不打印歌词；不由 AI 听写或翻译歌词。** 为什么：版权；本仓库不含任何歌词和歌曲。
9. **改一段，其后的字幕、冲击帧、配乐、歌词时间全部平移。** 维护一张时间平移表，所有阶段的时间常量按剪前时间线写、经过同一个 `shift()`。为什么：作者剪了 20 帧，5 处冲击帧的帧号、剪点之后的字幕、配乐和歌词的偏移都要同步改。
10. **每个阶段的输出各留一份，新版用新文件名。** 为什么：要从最早受影响的阶段重跑，不能在带字幕和配乐的成片上打补丁。
11. **每一步之后看一遍、听一遍，再进下一步。** 不要把五个步骤连着跑完才第一次看成片。

## 配乐和歌词的版权

本仓库不含任何音乐和歌词。配乐用**你有授权的歌**，歌词只用**用户提供的授权文本**；平台的版权识别可能命中，发布前的提醒见 `drama-publish` 的 copywriting.md。
