# 短剧发布：封面、文案、交付

成片定稿之后的最后一步：起片名、做封面、写文案、整理交付文件夹。**发布动作（登录、上传、勾选声明、点发布）由用户自己完成**，本 skill 只准备文件和清单。

## 交付清单

成片、横版封面、竖版封面三者共用同一个片名前缀，放在同一个文件夹，外加一份发布文案：

```
<片名>_发布/
├── <片名>.mp4                    成片（已嵌入横版封面）
├── <片名>_封面_横版_16比9.jpg
├── <片名>_封面_竖版_3比4.jpg
└── <片名>_发布文案.md
```

## 流程

| 步 | 做什么 | 细节 |
|---|---|---|
| 1 | 起片名：6–8 个候选，口吻各异，用户选 | [copywriting](references/copywriting.md) §1 |
| 2 | 先出**无字底图**，再让图像模型在底图上加**立体标题字** | [covers](references/covers.md) §2–3 |
| 3 | 横版 16:9 和竖版 3:4 **各出一张**，逐字核对标题 | [covers](references/covers.md) §3–4 |
| 4 | 把横版封面嵌入成片（`attached_pic`）；位置在字幕之后、配乐之前 | [covers](references/covers.md) §6；顺序见 `drama-postproduction` |
| 5 | 写三个平台的文案（抖音、小红书、B 站），作者视角，列"待核实清单" | [copywriting](references/copywriting.md) |
| 6 | 导出前检查；整理交付文件夹 | [export](references/export.md) |
| 7 | 交给用户发布，并说明每个平台用哪张封面、要勾选什么 | [export](references/export.md) §6 |

## 决策表

| 情况 | 做什么 |
|---|---|
| 想改封面标题的位置或字体 | **重新生成**：无字底图 + 旧封面都作为参考图，只改位置和字体描述（covers §5）；不要后期去挪 |
| 想要竖版封面 | 单独出，不要从横版裁：3:4 只占 16:9 宽度的约 42%，两个人物留不全 |
| 嵌入的封面在某个软件里不显示 | 正常：有些平台和聊天软件显示第一帧；上传时在发布页单独传封面（covers §6） |
| 要不要放大到 1080p | 默认保持 1536×864 原生；放大不增加细节（export §3） |
| 文案里想写对比、排名、版本名 | 先核实；不确定就用"印象里""我觉得"，或删掉（copywriting §5） |
| 配乐会不会被平台识别 | 会，授权不等于不被识别；提醒用户备好授权证明（copywriting §4） |

## 必须遵守的规则

1. **封面先出无字底图，再加标题。** 为什么：图像模型写中文标题常错笔画；分开之后标题错了只重出标题，改位置、改字体也不用重画人物。
2. **每次出图都逐字核对标题。** 错一笔就重出。为什么：模型不保证每一笔都对。
3. **标题不挡人物的脸、头发、头饰。** 位置用"画面宽度占比 + 字高占比"描述，不用"靠上一点"。
4. **横版和竖版各出一张。** 为什么：裁切会丢掉一个人物；平台要的封面比例不同（小红书竖版，抖音两版都传，B 站横版）。
5. **嵌入封面不能代替平台上的封面。** 为什么：有些平台和聊天软件显示的是视频第一帧。
6. **文案用作者视角，有人味，但中立、不拉踩。** 玩笑落在剧情里，不落在对真实产品的评价上。
7. **发布前勾选各平台的 AI 生成声明。** 成片里不烧声明，由发布页开关标识。
8. **提醒配乐（和歌词）的版权。** 本仓库不含音乐；平台的版权识别可能命中。
9. **事实性说法发布前核实**：版本名、排名、日期、"第一个"类断言。AI 起草的文案，把凭记忆写的事实列成"待核实清单"给用户。为什么：作者自己标出过一个需要用户再确认的版本名。
10. **"本地制作"要说准。** 视频在本地生成，但参考图和封面如果走了在线图像接口，就别写"全程本地"。
11. **不替用户点发布。** 为什么：发布是公开的、带账号的动作，撤回会留痕。

## 配置

封面出图用 config.yaml 的 `image_api`（兼容 OpenAI 图像接口的服务，需支持多张参考图的编辑接口）。成片规格读 `project.width / height / fps`。封面嵌入用 `scripts/embed_cover.sh`。
