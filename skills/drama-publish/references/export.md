# 导出与交付：交付文件夹、规格、分辨率取舍

> 什么时候读：成片和封面都定稿、要整理交付文件夹时；纠结"要不要放大到 1080p"时；发布前做最后一遍检查时。

可信度：规格和数字是《Gemini的复仇！》最终成片的**单次实测**（ffprobe / ffmpeg ebur128）。平台对分辨率、码率、文件大小的具体规则**未验证**，以发布页为准。

## 1. 交付文件夹

```
<片名>_发布/
├── <片名>.mp4                    成片（已嵌入横版封面）
├── <片名>_封面_横版_16比9.jpg
├── <片名>_封面_竖版_3比4.jpg
└── <片名>_发布文案.md
```

- 成片和两张封面**共用同一个片名前缀**，放在**同一个文件夹**。为什么：排在一起，传到手机或交给别人时一眼对应，不会拿错版本。
- 文件名里的全角标点（例：`！`）：作者的成片名带 `！`，上传正常；个别上传工具或聊天软件可能转义，出问题就先去掉再试 [未逐一验证]。
- 只放交付物。中间版本（`_无冲击帧`、`_字幕`、`_配乐` 等）和工程文件留在工作目录，成片本身当作 master 留一份。
- 成片太大不进 git 仓库，用外链。

## 2. 成片规格（示例）

| 项 | 值 |
|---|---|
| 容器 | MP4，`+faststart` |
| 视频 | H.264，yuv420p，1536×864，24 fps，约 8.2 Mbps |
| 音频 | AAC 256k，48 kHz，立体声 |
| 附图 | mjpeg，横版封面（`attached_pic`） |
| 时长 / 大小 | 224 秒 / 约 237 MB |
| 响度 | 整合 −14.9 LUFS，真峰值 −1.6 dBTP（[loudness.md](../../drama-postproduction/references/loudness.md)） |

## 3. 分辨率：保持原生，还是放大到 1080p

H3 的二采输出是 1536×864（16:9）。1080p（1920×1080）是它的 1.25 倍，比例不变，不会有黑边。

| 方案 | 好处 | 代价 |
|---|---|---|
| **保持 1536×864**（作者采用） | 就是生成分辨率，没有插值；文件小；不多一次重编码 | 平台按像素或高度划分清晰度档位时，可能不被标成"1080P" [未验证] |
| 放大到 1920×1080 | 凑平台的 1080P 档位 [未验证] | 放大**不增加细节**，软的地方只会更软；多一次重编码；文件更大 |

建议：
- **默认保持原生分辨率**，原生版本作为 master。
- 要放大，就在**所有后期做完之后**对成片整体放大一次，只重编码主画面，声音和封面流直接复制（命令未验证，先在小片段上试）：
  `ffmpeg -i 成片.mp4 -map 0:v:0 -map 0:a -map 0:v:1? -filter:v:0 scale=1920:1080:flags=lanczos -c:v:0 libx264 -crf 16 -preset slow -pix_fmt yuv420p -c:v:1 copy -c:a copy -disposition:v:1 attached_pic -movflags +faststart 成片_1080p.mp4`
  字幕和歌词的参数是按 1536×864 写的，放大会等比放大它们，所以不要在放大之后再叠字幕。
- 用 AI 超分（例：SeedVR2）作者试过，没有采用，原因见 `h3-video` 的 tried-and-dropped.md。
- 拿不准时，把两个版本都以"仅自己可见"传到平台，在手机上比较**平台转码后**的画质 [作者没做过这个对比]。画质以你看原片为准，不要只看缩略图。

## 4. 帧率与码率

- **保持 24 fps**，不为平台转成 30 fps：H3 就是按 24 fps 生成的，转帧率要重复或混合帧，会引入抖动 [未实测]。早期剪辑方案里写的"1080p、30 帧"是出片之前的估计，已放弃。
- 码率不用追高：平台会重新压缩。作者的成片约 8.2 Mbps，上传后画质以平台页面上看到的为准。
- 竖屏手机播放横屏片会有黑边。作者没有做竖版成片（需要重新构图和重新生成，不在这个 skill 范围）；竖版只做封面。

## 5. 导出前检查

1. **流**：
   `ffprobe -v error -show_entries stream=index,codec_type,codec_name,width,height,r_frame_rate:stream_disposition=attached_pic -of default=nw=1 成片.mp4`
   应有 h264（1536×864、24/1）、aac、mjpeg（`attached_pic=1`）。
2. **时长**：画面流和音频流的时长相差不超过 1 帧（0.042 s）。
3. **响度**：整合约 −15 LUFS，真峰值 ≤ −1.5 dBTP（量法见 loudness.md）。
4. **从头到尾带声音看完一遍**，不是抽看：字幕有没有错字、有没有压到画面边缘；每处冲击帧；配乐结尾和最后一句台词；片尾有没有多余的黑场或静音。再用手机看一遍。
5. **文件大小**和平台上传限制：作者的 237 MB 上传没有遇到问题（单次）；限制以发布页为准。
6. **版本记录**：成片文件名或旁边的记录里写明是哪一版、哪天导出、量到的响度。

## 6. 发布动作由用户完成

本 skill 只**准备**文件夹和文案。登录账号、上传、选封面、勾选 AI 生成声明、点发布，都由用户自己做。为什么：发布是公开的、带账号的动作，发出去之后撤回会留痕。

交付时一并告诉用户：
- 哪张封面传到哪个平台（[covers.md](covers.md) 第 4 节）；
- 每个平台要勾选的声明，配乐版权提醒（[copywriting.md](copywriting.md) 第 4 节）；
- 文案里的"待核实清单"，让用户核实后再发；
- 发布后下载或播放一次平台上的版本，看转码后的画质是否可以接受 [建议]。
