# LoRA 搭配与对比方法

什么时候读：要给武戏挂 LoRA 链、想知道链上每一个管什么、想试新的 LoRA，或者要做一次公平的 LoRA 对照时。

结论先说：**武戏挂五个 LoRA 的链，文戏一个都不挂。** 链里的 LoRA 全部是社区发布的，本仓库不分发；文件名写进 `config.yaml` 的 `models.fight_loras`。

## 武戏 LoRA 链

在 `shots.json` 里按这个顺序写成 `"loras": [[文件名, 强度], ...]`，队列用 `LoraLoaderModelOnly` 逐个串在底模后面，再接 SigmaShift 和稀疏注意力。

| 顺序 | LoRA（公开名） | 强度 | 管什么 | 来源 |
|---|---|---:|---|---|
| 1 | DMAD 融合版（`minimax_h3_dmad_full_dareties_v4_step600`） | 0.8 | 加速加清晰，画面不油；融合了 DMAD 4 步版与 step600 版，兼顾收敛速度和提示词遵循。强度到 1 会过拟合、发油 | 金鱼的工作流 |
| 2 | MysticXXX（`MysticXXX_MMH3-V1`） | 0.35 | 低强度下用来去油、改善人体结构 | 原作者 alcaitiff；见下面的披露 |
| 3 | 速度滑块（`motion_speed_slider_mmh3_v1.1`） | 3 | 直接控制动作快慢，范围 −10 到 +10，作者建议不超过 5 | 金鱼的工作流 |
| 4 | H3_Combat_V2 | 0.65 | 武戏动作 | 四只兔子 |
| 5 | Motion_Repair_V2 | 0.35 | 运动修复，针对高动态下的残影和变形（按名称和作者说明；本仓库没有单独对照过它） | 四只兔子 |

金鱼的工作流里还有 `H3_Fight_Flow_V1`（0.35），作者没用。

可信度：整条链的组合是单次实测加多段出片确认（已验证能出片、作者看片认可）；每个 LoRA 各自的贡献**未验证**，因为没有做过逐个去掉的消融对照。

### 披露：MysticXXX 的来源

这个 LoRA 的原作者发布它时，用途是成人向内容的人体结构。金鱼把它以 0.35 的低强度当作去油和改善人体结构的组件，作者照做。是否下载和使用由使用者自己决定，并遵守所在地的法律和平台规则。没有做过"去掉它"的对照，所以不能保证去掉后画质不变，也不能保证没有影响（未验证）。

## 文戏为什么不挂

文戏一律不挂任何 LoRA。2026-11-21，作者用 LoRA 出了打戏之后的对白段，看片发现比打戏之前不挂 LoRA 的对白段更糊，于是对白段改回不挂，沿用打戏前的文戏配置重出。

- 速度滑块和 Combat 是给动作加速、加猛用的，对白段不需要（推断）。
- 自动清晰度指标不能替代看片：在作者片中的第一段武戏（f1，8 秒）上，挂链后指标从 5.7 升到 8.5（单次实测；指标是 1536×864 下拉普拉斯的平均绝对值，仅作辅助），但文戏的结论来自看原片。

### 过渡档（单次实测，未做对照）

打戏之间的静态对峙段，以及刚打完的几段，作者试过去掉速度滑块和 Combat，只保留 DMAD、MysticXXX、Motion_Repair 三个。开赛前的两个对峙段用了它，成片里留用了。打戏后的对白段随后统一改回不挂。一般情况照上面的两档选，不要自己发明第三档。

## 怎样做同提示词同种子的 LoRA 对比

目的：让画面差异只能来自 LoRA。

1. **固定一切：** 同一段提示词、同一个种子、同样的参考图、同样的首帧或同一个接续来源、同样的分辨率和二采参数。
2. **只改 `loras`：** 每个对照一个 take 号（队列用 `id` + `take` 判断是否已经出过，不换号会被当成已完成）。
3. **一次只加一个：** 无 LoRA → 只加 DMAD + MysticXXX → 再加速度滑块 → 再加 Combat → 再加 Motion_Repair。作者的 f1 对照就是这样递进的：不挂、DMAD + MysticXXX、完整五件套。
4. **连续跑完：** 在主机上没有别的负载时一口气排完，耗时才可比。
5. **打开 `save_stage1: true`：** 一采预览也保存下来，可以区分是 LoRA 改了构图，还是只改了二采的细节。
6. **看原片：** 全屏播放，不看缩略图。同时记下耗时、动作速度、有没有残影或形变、人脸是否清楚。规则见 [quality-eval.md](quality-eval.md)。
7. **换一个种子或一个镜头再确认一次：** 只有一个种子、一个镜头的结果只能写成"单次实测"。

`shots.json` 示例（只列有差别的字段，其余同 [recipes.md](recipes.md) 的文戏示例）：

```json
[
  {"id": "f1", "take": 601, "loras": []},
  {"id": "f1", "take": 602, "loras": [["<DMAD 文件名>", 0.8], ["<MysticXXX 文件名>", 0.35]]},
  {"id": "f1", "take": 603, "loras": [["<DMAD>", 0.8], ["<MysticXXX>", 0.35], ["<速度滑块>", 3.0],
                                       ["<Combat_V2>", 0.65], ["<Motion_Repair_V2>", 0.35]]}
]
```

## 试过但没留下的 LoRA

在开场文戏段 g1（10 秒）上，同提示词同种子，基准不挂 LoRA，对比：写实人像 LoRA（0.8）、电影感去油 V0.3（0.8）、电影感 V1.0（0.8）。作者看原片都认为偏软，没有采用。原因和其他放弃的方案见 [tried-and-dropped.md](tried-and-dropped.md)。

另外，吃猪侠的结论是在 Cobijada 底模上叠 LoRA 会变差。武戏链是例外：它只在武戏上用，并且是作者在武戏镜头上看片认可的组合。

## LoRA 与工作流类型要配对

官方模板与 LoRA 作者的配对是：FL2V 的 Turbo LoRA 配文生视频和首尾帧，Ref2V 的 Turbo LoRA 配参考生视频。作者早期的首尾帧工作流沿用了参考生视频的 LoRA，能跑，但换成 FL2V 4 步 LoRA 后同样的画面只要一半时间（960×544、90 帧、同首帧同提示词，120.6 秒对 60.2 秒，单次实测）。文件名里的 `8step` 是 LoRA 的版本号，不等于实际采样步数。
